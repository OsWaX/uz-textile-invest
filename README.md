# Портал управления проектами Проектного офиса

Информационная система Проектного офиса заместителя министра по текстильной
промышленности — учёт экспортных и инвестиционных проектов, соглашений,
дорожных карт и зарубежных визитов по девяти регионам мира.

**Заказчик:** Проектный офис заместителя министра по текстильной промышленности
Агентства по развитию легкой промышленности при Кабинете Министров Республики Узбекистан.
Система реализована по техническому заданию (ТЗ) версии 1.0.

Интерфейс системы — на русском языке.

## Как открыть портал прямо сейчас

Портал — это полноценное веб-приложение с сервером и базой данных, поэтому на
GitHub Pages он не работает: там размещаются только статические страницы.
Запустить его можно двумя способами.

### Способ 1. GitHub Codespaces — ничего устанавливать не нужно

1. Нажмите зелёную кнопку **«Открыть в GitHub Codespaces»** выше
   (или на странице репозитория: **Code → Codespaces → Create codespace**).
2. Подождите 2–3 минуты: GitHub сам создаст среду, установит Node.js
   и наполнит базу демонстрационными данными.
3. Портал запустится автоматически, и браузер откроет вкладку с адресом вида
   `https://…-3000.app.github.dev`. Если вкладка не открылась — перейдите на
   панель **PORTS** внизу окна и нажмите на значок глобуса напротив порта 3000.
4. Войдите: `admin@textile.gov.uz` / `Parol2026!`

Адрес виден только вам, пока вы не откроете к нему доступ (панель **PORTS** →
правая кнопка мыши → *Port Visibility → Public*). Среда останавливается сама
после 30 минут простоя; при следующем открытии портал запустится снова.

Бесплатным аккаунтам GitHub доступно около 60 часов работы Codespaces в месяц —
для демонстрации и проверки этого достаточно.

### Способ 2. На своём компьютере

Нужен только **Node.js 22.5 или новее** ([скачать](https://nodejs.org)).

```bash
git clone https://github.com/OsWaX/uz-textile-invest.git
cd uz-textile-invest
npm run seed
npm start
```

Откройте `http://localhost:3000`. Команда `npm install` не нужна — внешних
зависимостей у системы нет.

> **Для постоянной эксплуатации** Codespaces не подходит: это среда разработки.
> Порядок установки на сервер министерства описан в
> [`docs/deployment.md`](docs/deployment.md). Требование раздела 11 ТЗ —
> размещение серверов на территории Республики Узбекистан, поэтому внешние
> облачные площадки для рабочей эксплуатации не подходят.

## Быстрый запуск

Требуется **Node.js 22.5 или новее**. Внешние зависимости не нужны — `npm install`
не требуется, папка `node_modules` не создаётся.

```bash
git clone https://github.com/OsWaX/uz-textile-invest.git
cd uz-textile-invest

npm run seed     # создать базу и заполнить её демонстрационными данными
npm start        # запустить сервер
```

Портал откроется на `http://localhost:3000`.

**Демонстрационные учётные записи** (пароль у всех — `Parol2026!`):

| Адрес | Роль | Что видно |
|---|---|---|
| `admin@textile.gov.uz` | Администратор | Полный доступ, панель администрирования, журнал аудита |
| `europe@textile.gov.uz` | Проектный менеджер по Европе | Создание записей без права изменения, свой регион |
| `observer@textile.gov.uz` | Наблюдатель | Только просмотр и выгрузка отчётов |

Ещё восемь менеджеров: `cis@`, `me@`, `southasia@`, `eastasia@`, `apac@`,
`namerica@`, `latam@`, `africa@` (все `@textile.gov.uz`).

Команда `npm run reset` пересоздаёт демонстрационные данные с нуля.

### Удаление демонстрационных данных перед реальной работой

```bash
npm run clean              # удалить проекты, компании, визиты, встречи, контакты,
                           # файлы, комментарии, уведомления и журнал аудита
npm run clean -- --users   # дополнительно удалить демонстрационные учётные записи
npm run clean -- --fields  # дополнительно удалить поля конструктора форм
npm run clean -- --all     # всё перечисленное выше
```

Команда показывает, что именно будет удалено, и запрашивает подтверждение —
нужно ввести слово `УДАЛИТЬ`. Перед удалением создаётся резервная копия базы
рядом с `data/portal.db` (файл вида `data/portal-backup-20260830T141054.db`).
Флаг `--no-backup` отключает копию, `--yes` пропускает подтверждение
(обязателен при запуске из скрипта, без интерактивного терминала).

Сохраняются в любом случае: структура базы, справочники (регионы мира, страны,
14 областей Узбекистана, статусы, отрасли) и настройки системы. Нумерация
проектов и визитов после очистки начинается заново с `0001`, все активные
сессии завершаются.

С флагом `--users` остаётся одна учётная запись администратора —
`admin@textile.gov.uz` или указанная в `ADMIN_EMAIL`. Если у неё был
демонстрационный пароль, он заменяется новым, и команда выводит его в консоль.

Полностью пустую систему можно получить и вручную: остановить сервер, удалить
`data/portal.db` и содержимое `data/uploads`, затем выполнить `npm start` —
при первом запуске система создаст схему, справочники и единственную учётную
запись администратора, напечатав её пароль в консоли.

Отдельные записи удаляются прямо в интерфейсе: они попадают в
**Администрирование → Корзина**, где их можно восстановить или удалить навсегда.

> Демонстрационные учётные записи предназначены только для ознакомления.
> Перед вводом в эксплуатацию выполните `npm run clean -- --all` либо запустите
> систему на пустой базе.

## Что реализовано

Соответствие разделам ТЗ подробно описано в [`docs/tz-compliance.md`](docs/tz-compliance.md).

### Проекты и соглашения (раздел 3 ТЗ)
Карточка записи со всеми полями P-01…P-15: тип записи, отрасль, направление
(экспорт/инвестиции), страна с автоматическим определением региона, компания,
сумма в любой валюте, ответственный менеджер, статус с историей изменений,
контактные лица партнёра, дорожная карта, вложения, лента комментариев и
произвольные поля из конструктора форм.

Дорожная карта отображается одновременно как чек-лист и как горизонтальная
диаграмма сроков. Просроченные этапы вычисляются автоматически.

Реестр проектов: сортировка по колонкам, фильтры по всем измерениям,
полнотекстовый поиск (включая контакты и комментарии), сохранённые выборки,
цветовая индикация просрочек и «замерших» проектов.

### Узбекская сторона проекта и регионы реализации (дополнение № 1 к ТЗ)
У проекта указываются **местные партнёры** — одна или несколько узбекских
организаций с ролью в проекте, — и **регионы реализации**: один или несколько из
14 регионов страны, для каждого обязателен город или район и необязателен объём
инвестиций. Дашборд показывает портфель в разрезе регионов Узбекистана вместе со
схематической картой страны, счётчиком охваченных регионов и объёмом, ещё не
распределённым по площадкам. Регионы заполняются у инвестиционных проектов;
администратор может распространить поле и на экспортные записи.

### Компании и партнёры (раздел 4 ТЗ)
Независимый справочник компаний. Карточка компании показывает **все её проекты,
все встречи и итоговые суммы соглашений**. При создании система предупреждает о
возможных дубликатах; администратор может объединить дубликаты с переносом всех
связанных данных.

### Визиты и встречи (раздел 5 ТЗ)
Выездные визиты и приём иностранных делегаций: направление, страна, города,
даты, статус, цель, состав делегации (сотрудники из справочника и внешние
участники), встречи, вложения и итоги визита.

Встречи группируются в программу по дням и печатаются как одностраничный
документ с бланком министерства. Встречу можно связать с проектом — тогда она
появляется в истории этого проекта.

### Дашборд и аналитика (раздел 6 ТЗ)
Ключевые показатели, воронка проектов по статусам, разрезы по отраслям,
направлениям, регионам, странам и менеджерам, динамика по месяцам,
интерактивная карта регионов и **панель внимания**: просроченные этапы, сроки
ближайшей недели, «замершие» проекты и несогласованные встречи перед визитом.

Менеджер по умолчанию видит свой регион, администратор — весь офис.

### Уведомления (раздел 7 ТЗ)
Три канала: центр уведомлений в системе, электронная почта (SMTP) и Telegram-бот;
каждый сотрудник выбирает каналы в профиле.

Напоминания за 7, 3 и 1 день до срока этапа (интервалы настраиваются); в день
просрочки — уведомление ответственному и эскалация администратору и руководителю
офиса; события по проектам, визитам и заявкам; еженедельная сводка по
понедельникам. Планировщик работает внутри приложения, отдельный cron не нужен.

### Отчёты, выгрузки и календарь (раздел 8 ТЗ)
Любой отфильтрованный список выгружается в **Excel (.xlsx)** и CSV одним
нажатием; произвольные поля включаются в выгрузку автоматически. Готовые отчёты:
сводка по портфелю (книга из пяти листов) и отчёт по работе менеджеров.
Карточка проекта и программа визита печатаются в PDF средствами браузера с
бланком министерства.

Календарь на месяц и списком, лента `.ics` для подписки в Outlook и Google Календаре.

### Панель администратора (раздел 9 ТЗ)
**Конструктор форм** — администратор добавляет собственные поля в формы проектов,
визитов и компаний без участия программиста: текст, число, деньги, дата, списки,
**голосование**, флажок, файл, ссылка, выбор пользователя. Для каждого поля
задаются название на трёх языках, обязательность, подсказка, позиция и право
менеджера заполнять его. Поля попадают в фильтры и выгрузки. Отключение поля
скрывает его в новых записях, сохраняя исторические данные.

Также: управление пользователями, справочники (отрасли, статусы, типы записей,
валюты, привязка стран к регионам), настройки напоминаний и безопасности,
курсы валют, журнал аудита и корзина с восстановлением в течение 30 дней.

### Дополнительные возможности (раздел 10 ТЗ)
Журнал аудита (кто, что, когда, старое значение → новое), доска проектов с
перетаскиванием карточек между статусами, адаптивный интерфейс для телефона,
`@упоминания` в комментариях с уведомлением, глобальный поиск по клавише `/`,
версионность документов, светлая и тёмная темы.

## Роли и права доступа

Матрица прав из раздела 2.2 ТЗ реализована **на стороне сервера** — интерфейс
лишь скрывает недоступные действия, но решение всегда принимает сервер.

| Действие | Администратор | Проектный менеджер | Наблюдатель |
|---|:---:|:---:|:---:|
| Создание проекта, соглашения | ✔ | ✔ | — |
| Изменение полей записи | ✔ | — | — |
| Удаление записи | ✔ | — | — |
| Добавление этапа дорожной карты и вложений | ✔ | ✔ | — |
| Изменение и удаление этапа | ✔ | — | — |
| Отметка о выполнении своего этапа | ✔ | ✔ | — |
| Создание визита и встреч | ✔ | ✔ | — |
| Изменение и удаление визита, встречи | ✔ | — | — |
| Заявка на исправление | — | ✔ | — |
| Пользователи, справочники, конструктор форм | ✔ | — | — |
| Просмотр всех проектов | ✔ | ✔ | ✔ |
| Выгрузка отчётов | ✔ | ✔ | ✔ |
| Журнал аудита | ✔ | — | — |

**Заявка на исправление** (п. 2.3 ТЗ). Менеджер не может изменить созданную
запись, поэтому нажимает «Запросить исправление», описывает ошибку, и
администратор одобряет или отклоняет запрос. Обе операции попадают в журнал.

## Технологии

ТЗ (раздел 12) допускает эквивалентный стек. Выбрано решение **без внешних
зависимостей времени выполнения** — это упрощает установку в закрытом контуре
государственного дата-центра, где доступ к внешним репозиториям пакетов может
отсутствовать, и снимает риски цепочки поставок.

| Слой | Реализация |
|---|---|
| Сервер | Node.js 22 LTS, встроенный модуль `node:http` |
| База данных | SQLite (`node:sqlite`), схема на стандартном SQL |
| Интерфейс | Модули ES без сборки, SVG-графика собственной реализации |
| Хранение файлов | Файловая система сервера (каталог настраивается) |
| Уведомления | Собственный SMTP-клиент и Telegram Bot API |
| Выгрузки | Собственный генератор `.xlsx` (ZIP + OOXML), CSV, iCalendar |
| Развёртывание | Docker и docker compose |

Внешних зависимостей — **ноль**. Схема базы данных переносится на PostgreSQL;
порядок перехода описан в [`docs/data-model.md`](docs/data-model.md).

## Настройка

Скопируйте `.env.example` в `.env`. Ключевые параметры:

| Переменная | Назначение |
|---|---|
| `SESSION_SECRET` | Ключ подписи сессий. **Обязателен в продакшене**, не короче 32 символов |
| `SECURE_COOKIES` | `1`, если приложение работает за HTTPS-прокси |
| `DB_PATH`, `UPLOAD_DIR` | Расположение базы данных и вложений |
| `MAX_UPLOAD_MB` | Предельный размер файла, по умолчанию 25 МБ |
| `SMTP_*` | Почтовый сервер; если не заполнен — канал «почта» отключён |
| `TELEGRAM_BOT_TOKEN` | Токен бота; если не заполнен — канал Telegram отключён |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Первая учётная запись администратора при создании базы |

Ключ подписи сессий:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Пороговые значения, интервалы напоминаний, тайм-аут сессии, курсы валют и
реквизиты организации меняются в интерфейсе: **Администрирование → Настройки**.

## Развёртывание

```bash
cp .env.example .env      # заполните SESSION_SECRET и ADMIN_PASSWORD
docker compose up -d
```

Контейнер `backup` ежедневно сохраняет копию базы и архив вложений в каталог
`./backups` и удаляет копии старше 30 дней.

Полный порядок установки, настройка HTTPS-прокси, резервное копирование и
проверка восстановления описаны в [`docs/deployment.md`](docs/deployment.md).

## Тестирование

```bash
npm test                                        # 34 теста: приёмка, безопасность, модули
node --experimental-vm-modules scripts/check-frontend.js   # синтаксис клиентских модулей
```

`tests/acceptance.test.js` воспроизводит сценарии приёмки из раздела 14.1 ТЗ:
ограничение прав менеджера, карточка компании со всеми проектами, автоматическая
просрочка этапа с уведомлениями и эскалацией, добавление поля-голосования через
конструктор форм с проверкой его появления в выгрузке, программа визита из пяти
встреч, совпадение показателей дашборда с расчётом по базе, корректность книги
Excel, журнал аудита со старыми и новыми значениями, восстановление из корзины.

`tests/security.test.js` проверяет хранение паролей, сложность пароля, отсутствие
самостоятельной регистрации, блокировку после неудачных входов, тайм-аут сессии,
двухфакторную аутентификацию, защиту от подделки межсайтовых запросов, заголовки
безопасности, отсутствие выхода за пределы каталога `public`, ограничение типов
