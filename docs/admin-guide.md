# Руководство администратора

Роль **«Администратор»** обладает полными правами: изменение и удаление любых
записей, управление пользователями, настройка форм и справочников, доступ к
журналу аудита. Как правило, эту роль получают заместитель министра и
руководитель Проектного офиса.

---

## 1. Пользователи

**Администрирование → Пользователи**

Самостоятельная регистрация в системе отключена. Учётные записи создаёт только
администратор.

### Создание учётной записи

«+ Новый пользователь». Заполните адрес электронной почты (он же логин), ФИО,
должность, роль и регион ответственности. Временный пароль формируется
автоматически — передайте его сотруднику по защищённому каналу. При первом входе
система потребует сменить пароль.

Роли:

- **Администратор** — полный доступ;
- **Проектный менеджер** — создание записей без права изменения (раздел 2.2 ТЗ);
- **Наблюдатель** — только просмотр и выгрузка отчётов, для приглашённых
  наблюдателей и руководства министерства.

Регион определяет, что менеджер видит по умолчанию на дашборде и в фильтрах.
Читать записи других регионов может любой сотрудник — это требование ТЗ.

### Обслуживание учётных записей

| Кнопка | Действие |
|---|---|
| ✎ | Изменить ФИО, должность, роль, регион, контакты, отключить учётную запись |
| 🔑 | Сбросить пароль — выдаётся новый временный, все сессии завершаются |
| 🔓 | Сбросить двухфакторную аутентификацию (сотрудник потерял телефон) |
| ⏻ | Снять блокировку после неудачных попыток входа |

Отключение учётной записи немедленно прекращает все её сессии. Данные, созданные
сотрудником, сохраняются. Последнего активного администратора отключить нельзя.

## 2. Конструктор форм

**Администрирование → Конструктор форм**

Позволяет добавлять собственные поля в формы проектов, визитов и компаний без
участия программиста (раздел 9.1 ТЗ).

### Типы полей

| Тип | Назначение |
|---|---|
| Однострочный текст, многострочный текст | Произвольные сведения |
| Число, денежная сумма | Числовые показатели |
| Дата | Контрольные даты |
| Один вариант из списка, несколько вариантов | Классификация по своим значениям |
| **Голосование** | Сотрудники офиса голосуют, результат виден в карточке |
| Да / Нет | Признак |
| Файл, ссылка | Документы и внешние ресурсы |
| Пользователь | Выбор сотрудника |

### Параметры поля

- **Название** на русском, узбекском и английском языках;
- **обязательность** заполнения;
- **подсказка** для пользователя;
- **право менеджера заполнять поле** — если снять, поле заполняет только администратор;
- **варианты ответа** для списков и голосований.

Новое поле сразу появляется в форме, в выгрузках Excel и CSV.

**Отключение поля** скрывает его в новых записях, но сохраняет исторические
данные — ранее внесённые значения остаются в базе и в выгрузках.

Тип поля и форму после создания изменить нельзя — это защищает уже внесённые
данные. Если тип выбран неверно, отключите поле и создайте новое.

## 3. Справочники

**Администрирование → Справочники**

Редактируются: отрасли, типы записей, статусы проектов, статусы визитов, статусы
встреч, валюты, а также привязка стран к регионам ответственности.

Для каждого значения задаются код (латиницей, используется в базе и выгрузках),
название на трёх языках и цвет метки.

Значение, которое используется в записях, отключить нельзя — сначала переведите
эти записи в другой статус.

**Страны и регионы.** Регион проекта определяется автоматически по стране.
Если распределение регионов между менеджерами изменилось, переназначьте страны
в таблице внизу раздела — ранее созданные записи автоматически попадут в новый
регион.

## 4. Настройки

**Администрирование → Настройки**

### Напоминания и контроль сроков

| Настройка | По умолчанию | Смысл |
|---|---|---|
| Напоминания за N дней | 7, 3, 1 | За сколько дней предупреждать о сроке этапа |
| Эскалация просроченных | включена | Уведомлять руководство о просрочках |
| День и час еженедельной сводки | понедельник, 08:00 | Время рассылки сводки |
| Порог «замершего» проекта | 30 дней | Через сколько дней без активности пометить проект |
| Предупреждение о несогласованных встречах | 7 дней | За сколько дней до визита проверять статусы встреч |

Кнопка **«Запустить проверку сроков сейчас»** выполняет все проверки немедленно —
удобно при приёмке и для контроля настроек. Повторные уведомления не дублируются.

### Безопасность и хранение

- **Тайм-аут неактивной сессии** — по умолчанию 30 минут;
- **Обязательная двухфакторная аутентификация** — при включении сотрудники
  обязаны подключить её при следующем входе;
- **Срок хранения в корзине** — по умолчанию 30 дней.

### Курсы валют

Используются для сводных сумм на дашборде и в отчётах: суммы во всех валютах
приводятся к долларам США. Обновляйте курсы при заметных изменениях.

### Реквизиты организации

Название офиса и министерства отображаются в интерфейсе и на печатных формах.

## 5. Заявки на исправление

**Заявки на исправление** (в разделе «Аналитика»)

Проектные менеджеры не могут изменять созданные записи, поэтому ошибки
исправляются через заявку. Значок с числом в меню показывает количество
нерассмотренных запросов.

Порядок работы:

1. Откройте заявку и прочитайте описание ошибки.
2. Перейдите в карточку записи по ссылке и внесите исправление.
3. Вернитесь к заявке и нажмите **«Одобрить»**, указав, что было изменено.
   Если исправление не требуется — **«Отклонить»** с пояснением.

Автор заявки получит уведомление. Обе операции — правка записи и решение по
заявке — фиксируются в журнале аудита.

## 6. Журнал аудита

**Администрирование → Журнал аудита**

Фиксируются: создание, изменение, удаление и восстановление записей, смена
статусов, отметки о выполнении, комментарии, загрузка файлов, входы в систему и
неудачные попытки входа, выгрузки данных, изменения настроек и управление
пользователями.

Для каждого изменения сохраняются **старое и новое значение поля**, автор, время
и IP-адрес. Именно журнал обеспечивает гарантию, заявленную в ТЗ: данные нельзя
изменить незаметно.

Фильтры: по действию, типу записи, пользователю, периоду и тексту. Поиск идёт и
по значениям изменённых полей — можно найти, кто и когда поменял конкретную сумму.

Журнал доступен только администратору.

## 7. Корзина

**Администрирование → Корзина**

Удалённые записи хранятся 30 дней (срок настраивается) и могут быть восстановлены.
Показывается, сколько дней осталось до окончательного удаления.

- **Восстановить** — вернуть запись в работу;
- **Удалить навсегда** — необратимо удалить запись вместе с вложениями и
  комментариями.

Очистка устаревших записей выполняется автоматически при запуске приложения.

## 8. Компании: объединение дубликатов

При создании компании система предупреждает менеджера о похожих названиях, но
дубликаты всё же появляются. В карточке компании нажмите **«Объединить дубликат»**,
найдите вторую запись и подтвердите.

Все проекты, встречи, контакты и файлы дубликата переносятся в основную карточку,
дубликат перемещается в корзину. Операция фиксируется в журнале аудита.

Компанию со связанными проектами удалить нельзя — сначала переназначьте или
удалите её проекты (требование целостности данных, раздел 11 ТЗ).

## 9. Отчётность для руководства

**Отчёты и выгрузки**

- **Сводный отчёт по портфелю** — книга Excel из пяти листов: по регионам,
  отраслям, статусам, менеджерам и полный реестр проектов. Фильтры в верхней
  части страницы применяются к отчёту.
- **Отчёт по работе менеджеров** — проекты, подписанные соглашения, выполненные
  этапы, доля выполненных в срок, просрочки, визиты по каждому сотруднику.
- **Выгрузка реестров** — проекты, этапы дорожных карт, визиты, компании в Excel
  или CSV. Произвольные поля включаются автоматически.
- **Печатные документы** — карточка проекта и программа визита с бланком
  министерства печатаются кнопкой «Печать / PDF».

Дашборд также печатается — удобно для доклада заместителю министра.

## 10. Регламент обслуживания

**Ежедневно.** Просмотреть панель внимания на дашборде; рассмотреть заявки на
исправление.

**Еженедельно.** Проверить просроченные этапы и «замершие» проекты; убедиться,
что резервные копии создаются (каталог `./backups` или `/backup/daily`).

**Ежемесячно.** Просмотреть журнал аудита на предмет неудачных попыток входа;
проверить список активных учётных записей; обновить курсы валют.

**Ежеквартально.** Провести проверку восстановления из резервной копии на
тестовой среде (порядок — в [`deployment.md`](deployment.md), раздел 6).

## 11. Обучение сотрудников

ТЗ предусматривает два занятия. Рекомендуемая программа:

**Занятие для администратора (2 часа).** Управление пользователями; конструктор
форм на примере создания поля-голосования; справочники и настройки; заявки на
исправление; журнал аудита и корзина; отчётность для руководства; резервное
копирование и восстановление.

**Занятие для проектных менеджеров (1,5 часа).** Вход и двухфакторная
аутентификация; правило «созданное не изменяется» и заявки на исправление;
создание проекта с дорожной картой; отметка выполнения с приложением материалов;
компании и защита от дубликатов; визиты и программа встреч; фильтры, сохранённые
выборки и выгрузки; работа с телефона; каналы уведомлений.
